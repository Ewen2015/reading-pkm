# 第二大脑

不是书库，是一个**会挑视野、会下判断、会认错**的思考伙伴。

**它交付的是意见，不是读书报告。**"这本书说……那本书说……"是失败形态。

## 书库长什么样

**代码和数据分开放**：skill 目录里只有写法、工具和路由表，书库（卡片＋原笔记＋题集＋索引）
在仓库根的 `library/` 下。`brain.py` 按这个顺序找数据，用第一个找到的：

1. `$SECOND_BRAIN_HOME`——想放仓库外（挂网盘、跟别的机器共享）就设它；
2. **skill 目录的兄弟目录 `library/`**——本仓库的默认形态；
3. `~/.local/share/second-brain`——前两个都没有时兜底，在那里初始化一个空书库。

```
library/                          ← 数据面，真相在这里
|-- index.md                     视野索引：按维度排，每维只列代表书。唯一常读的文件，**生成物，别手改**
|-- index.json                   机器层索引，recall 读它，模型永远不看（生成物）
|-- books/<slug>.md              每本一张卡，只读选中的那几张
|-- notes/<slug>.md              read-a-book 的原笔记，深度层（只在深读/核对时读）
|-- evals/recall.jsonl           固定题集 + baseline.json：检索质量的回归基线
`-- .recall-log.jsonl            本机 recall 日志，不入库（写在 .gitignore 里）

skills/second-brain/              ← 代码面，可单独拷走
|-- SKILL.md
|-- references/                  写法与挑法：dimensions.md（路由表）· retrieval.md · cards.md
`-- scripts/brain.py             recall / index / check / eval / add
```

路径不写死是有意的：`brain.py` 是纯标准库脚本，别人想单独拷去用，数据就该能放在别处。
所以它认上面那套解析顺序，不认"仓库在哪"——换个 cwd 跑，结果一样。

书不是 skill，是**文件**。真正做成独立 skill 会让每本书的描述常驻上下文——那正是这里要省的东西。
这里的等价物是「index 当指路牌，卡片当按需加载的正文」。

**扩展性来自"按维度排，不按书排"**：书涨到几百上千本，`index.md` 的大小只随维度数变化、
不随书数变化（1000 本时仍约 2K tokens）。每维只列**有帮助的那几本**，不是全部——
它是指路牌，不是书目。

## 四步

1. **拆问题**——把问题压成一句话，找出张力（"要不要"／"哪个更好"／"为什么做不到"），
   以及它牵涉哪几个思考维度；同时先想一下**你自己倾向的结论是什么**，后面要论证它。
2. **挑维度**——读 `index.md` 挑 2–4 个维度；拿不准就跑 `brain.py recall "<问题>"`，
   它对四路（维度／字面／小节／沿「对撞」边）各投一票做融合。**关键判据不是"哪本书谈过
   这个话题"，而是"哪个视野能给这题加一维"。**
3. **取书并加载**——从 recall 的候选里挑：每本都带着 `命中`／`置信`／`边界`／`可当反方` 四行，
   挑的时候就直接用上。判断型问题一般取 2 本：一本最支撑你的结论，一本能当**最强反方**
   （优先用输出里"可当反方"给的那本，它是库内、卡片已登记过的）。第 3 本除非用户点名，否则不读。
4. **回答**——按下面结构：结论 → 论据 → 反方 → 共用假设 → 更高维反思。
   每本书的**完整视野不进答案**，只有支撑结论和反方的那几句进。

## 回答的结构

```
**结论**：一句话，可反驳，标清这是你的判断（不是书里的话）。1–3 句。

**论据**（2–4 条，按权重排）
- 主张 → 依据（《书名》· 作者，章节/页）→ 它怎么支撑结论。
- 卡片 `lens` 是取景器不是论据；论据必须落回卡里的原句或命题。
- 分不清是原句、转述还是你推的，就在这里标。

**反方**（替它说足，不许打稻草人）
- 反面主张：写成它最有说服力的版本。
- 它的依据：《书名》· 作者，位置；书里没有就说"这是我用 X 推的"。
- **结论凭什么仍然压倒它**：①前提不成立 ②适用条件不符 ③权重取舍不同 ④反方越出了自己的边界。
  四选一或并列，别用"总之"糊过去。
- 压不倒就**直说压不倒**：把结论降级成条件性的，写明取决于什么。

**这个讨论的共用假设**（1–3 条）
- 正反双方都默认、但这一轮没被检验的东西。逐条问：它不成立时，结论会怎么变？
- 只写真的撑着结论的那些，凑数的不写。

**更高一层的反思**
- 问题本身是不是被设窄了？换一种问法会不会有别的解。
- 换一个坐标（时间／尺度／他人）看，结论会不会反过来。
- 这个结论最可能错在哪。

**出处与不确定**
- 原句（引号 + 位置）／转述（"大意是"）／我的推论（"我用它推的"），三种分开。
- 二手来源在这里说明。
```

判断型问题（该不该、怎么办）**不说"没有相关书"**——用维度表取视野，最后必须落到一个结论。
只有事实型问题（谁、哪年、原文怎么说）找不到时，才直说"书里没有"。

## 上下文预算

| 层 | 什么时候进上下文 | 每本/每次 |
| --- | --- | --- |
| `SKILL.md` | 命中 skill 时 | ~1.6K tokens |
| `index.md` | 挑维度时 | **~1K，不随书数增长**（1000 本约 2K） |
| `index.json` | **从不进上下文** | 机器层，只有脚本读 |
| `library/books/<slug>.md` | **只读选中的 1–3 张** | 每张 ~1.4–2K |
| `library/notes/<slug>.md` | 只在用户要深读或核对时 | 每本 ~6–10K |

事实型问题读 1 张；判断型问题通常读 2 张（论据 + 反方），最多 3 张，一次问答 ≈ 4–6K tokens。
路径都以 `library/` 起算（书库换了位置就换成解析出来的那个根，见上一节）。
**不许把 `books/` 整个读完**，也不许把 `index.md` 当书目去列全——它每维只有代表位。
原笔记比卡片大 5 倍，只有用户说"展开讲""原文怎么说的"时才读。

## 铁律

1. **每个观点都要有出处。** 格式 `（《书名》· 作者，章节/页）`。说不出出处的观点不要写。
2. **不许替书说话。** 只讲卡片里有的。卡里没覆盖这个角度，就说"这本书的卡里没谈这个"，
   不要凭印象补。**把作者的视野用到新问题上是可以的——但那是你的推论，必须标出来。**
3. **三种话必须分开**：原句（加引号 + 位置）／转述（"大意是"）／我的推论（"这是我用它的框架推的"）。
4. **二手来源要标出来。** 卡里 `source_type` 不是"一手"的，回答里就说一句。
   《纳瓦尔宝典》整本都是编者从推文和播客里整理的，引它等于引二手。
5. **区分两种"没有"。** 事实型问题找不到就直说"书里没有"；判断型问题必须落到结论。
   只有连相关维度都没有时，才说"书库里没有覆盖这个方向的视野"。
6. **卡里的「什么时候别用它」是护栏**，不是装饰。在它写明的失效场景里不要引它。
   `recall` 已经把每张卡的边界和置信摆在候选里了——没在回答里用上，等于白拿。
7. **挑书先挑维度。** 搜不到话题不要立刻说没有——先看 `index.md` 的维度表，
   问"哪个视野能给这题加一维"。
8. **给意见，不列清单。** 结论先行；论据只留支撑结论的。逐本转述书里的观点是读书报告，
   不是第二大脑——**书是论据的来源，不是答案的分段**。
9. **反方必须被处理掉，或坦白处理不掉。** 先替反方说足，再说清结论凭什么压倒它
   （前提／条件／权重／越界）。势均力敌就承认势均力敌，把结论降级为条件性的。
   **和稀泥和硬给结论，是两种同样严重的失败。**
10. **共用假设与更高维反思是必答项。** 共用假设要真的同时撑着正反两方；
    更高维反思要落到"问题被设窄在哪、换坐标会怎样"，不是感想。
11. **结论是你的，责任也是你的。** 书只提供视野和依据；最终那个"所以我认为"必须由你下，
    且必须标明它是你的推论。

## 检索质量怎么守

词表是这套检索唯一的可调项，凭手感改会越改越坏。改完 `dimensions.md` 或卡片后跑一次
（相对路径以本 skill 目录为基准；从仓库根目录跑时用 `python3 skills/second-brain/scripts/brain.py`）：

```bash
python3 scripts/brain.py eval            # P@k / R@k / MRR / 维度命中率 +「未调参」那一行
python3 scripts/brain.py eval --check    # 与基线比，回退超过 0.05 就退出码 1
python3 scripts/brain.py eval --baseline # 确认是净改善后，重新记基线
```

- 看**「未调参」那一行**：标了 `tuned` 的题，是它那句说法后来被补进了词表——那只能证明
  词表补对了，不证明泛化。
- 这个数只回答"候选里有没有该出现的书"，**不回答答案好不好**；题少，一道值好几个百分点，
  只看同一套题改前改后有没有变好。
- **`eval --check` 失败先看基线新旧。** 如果这一轮没有改词表/触发器，先看
  `library/evals/baseline.json` 是不是上一批 `add` 之后没更新；旧基线造成的回退不是新卡的问题。
  不要静默重记基线，先把「基线未更新」写进报告。
- 用户换个说法就搜不到 → 把那个说法补进对应维度的「问法」；这是最主要的修法。
  详见 [`references/retrieval.md`](references/retrieval.md)。

## 书库怎么长

读完一本新书后：

```bash
python3 scripts/brain.py add --notes <笔记文件路径> --slug <slug>
# 它会把笔记收进 notes/，并生成一张卡片骨架
# 按 references/cards.md 填完卡片（含 lens 与 dimensions），删掉末尾「待处理」整段
python3 scripts/brain.py index     # 重生成 index.md 与 index.json
python3 scripts/brain.py check     # 体检：字段、维度是否在表内、索引是否同步、关系边、死卡
python3 scripts/brain.py eval --check   # 改了词表或触发器时，确认没有把检索弄回退
```

- `lens`：这个作者看任何问题时习惯问的那一句，60 字内。
- `dimensions`：挂到 `references/dimensions.md` 的维度上，2–6 个。**维度数是人为固定的**，
  只有现有维度确实装不下这本书的视野时才加新的。
- `weight`（可选）：越高越可能占 `index.md` 每维的代表位；缺省 0。

**`notes/` 与 `books/` 一起入库**：原笔记含较多原书引文，属于深度层；卡片是可引用的提炼，
两者都进仓库，换机器不用重新生成。

`triggers` 仍是检索接口（写用户会说的话，供 `--topic` 模式用）；默认的维度路由用 `dimensions`。
发新卡时顺手在「与其他书」里写清对撞（两边都写）、填上 `confidence`——`check` 会查这两项，
反方臂也靠它们工作。
写法和字段口径见 [`references/cards.md`](references/cards.md)、
[`references/dimensions.md`](references/dimensions.md)。

如果这轮问答里发现了一个卡片没写、但确实成立的新关联，问用户一句要不要写回卡片——
书库是这样长起来的，不要自己默默改。
