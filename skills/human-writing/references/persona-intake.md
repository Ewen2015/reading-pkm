# 人设怎么读进来

**人设是输入，不是本 skill 的一部分。** `human-writing` 不绑定任何账号或作者：
调用方把它的人设交进来，本 skill 读它、照它写。第一个调用方是 `rednote-post`，
它传的是 [`skills/rednote-post/references/persona.md`](../../rednote-post/references/persona.md)。

**这也是一份输入，不是锁。** 一次调用里如果用户当次说了另一种语气，**以用户当次说的为准**；
换账号，就换一份人设文件。人设文件是默认值。

---

## 1. 一份人设文件该有什么

参照 `skills/rednote-post/references/persona.md` 的骨架，六节：

| 节 | 回答什么 | 不可省的原因 |
| --- | --- | --- |
| 账号／作者事实 | 这是谁、量级、地域 | 决定"我"站哪儿说话 |
| 他是什么人 | 位置与语气（平视？俯视？） | 决定能不能说"你应该" |
| 写法定式（若干条） | 开口、人称、重音、收尾、出处行……**每条附成品证据** | 这是可直接照抄的常量 |
| 可以摆动的 | 哪些只是"上次用了"、不是规定 | 防止把风格做成模板 |
| 反面清单 | 一出现就不像他的词／结构 | 机判词表的来源 |
| 写完自查 | 30 秒能过一遍的问题 | 交给模型自检 |

**证据很关键。** 一条"语气要平视"没有用；"他从不说'你应该'，他说'可以只带一个问题走'"才有用。
人设文件里每一条都该能指回一篇成品。

---

## 2. 把文件读成一张指纹表

读完人设文件，先填这张表，再动笔。文件没写全的维度，从成品里补（下一节）。

| 维度 | 要落成什么 | 例（司马读书） |
| --- | --- | --- |
| 开口 | 第一句是具体的东西（场景／数字／反直觉断言），还是概括 | "写了三行，删了两行，然后去洗了个碗。" |
| 人称 | 用"你"还是"我"；平视、俯视还是仰视 | 通篇"你"，平视 |
| 节奏 | 长句多还是短句多；有没有"一句单独成行" | 短句多，重点句单独成行 |
| 重音 | emoji 领起／单行／符号前缀／加粗 | emoji 领起 + `→` 行动项；**正文不能加粗** |
| 用词 | 高频词、口头禅、禁忌词 | 禁：首先／底层逻辑／抓手……（见反面清单） |
| 结构 | 段落推进还是编号条目 | 两种都用，**服从内容**，不设模板 |
| 收尾 | 回到读者身上，还是总结内容 | 回到读者；不给行动也给一个反问 |
| 必须留的 | 具体到能查的数字／页码／出处；一条"退一步看这本书" | 页码、版本行；一条"退一步看这本书" |

**指纹表填不满就别动笔。** 空着的维度，模型会用默认腔自动补上——那正是 AI 味的来源。

## 3. 没有人设文件时，从成品抽

有三五篇该人设的成品，就能抽出一份指纹：

1. **开口**：只看每篇第一句，它们是在给具体的东西，还是在给概括？
2. **人称与语气**：数"你／我"的出现，看有没有训话词（你应该、必须）。
3. **节奏**：随便挑一段，量句子长度，看有没有长短起伏。
4. **重音**：他都用什么标重点？出现频率多高？
5. **用词**：圈出反复出现的词（口头禅）；再圈出从来没出现过的、你觉得"他这种人不会说"的词。
6. **收尾**：把每篇最后两句单独拿出来看，是回到读者，还是总结内容？
7. **禁忌**：从上面第 5 条反推，写成一份"反面清单"。

抽完**附上证据**（哪一句、哪一篇），别只写结论——和上一节的要求一样。

## 4. 人设文件合约（给机判那半边用）

[`../scripts/human_check.py`](../scripts/human_check.py) 会从 `--persona` 指向的文件里
读**禁忌词**。认两种写法，二选一：

**写法一（推荐，一行声明，好维护）：**

```
禁忌词：首先｜其次｜综上所述｜赋能｜底层逻辑｜抓手
```

**写法二（围栏块，词多时清爽）：**

````
```banned
首先
其次
综上所述
```
````

- 关键词认 `禁忌词`／`禁用词`／`banned`（大小写不敏感）。
- 分隔符认 `｜`／`|`／`、`／`,`／`，`／`;`／空白。
- 没声明禁忌词的人设文件也能用，只是跑通用词表（`human_check.py` 的 `HARD_PHRASES`）。

**为什么要有这个合约**：`rednote-post` 的 `check_content.py` 不再自己抄一份 AI 味词表，
它 import `human_check`、读同一份 `persona.md` 的禁忌词行——**词表只有一个来源**，
改词只改一处（这正是 `rednote-post` 里"规则写进脚本才不退化"的同一条纪律）。

## 5. 冲突与更新

**优先级**：用户当次指令 > 人设文件 > 本 skill 的通用默认。

- 用户当次指定了别的语气／人设 → 先按用户说的写，写完可以问一句要不要写回人设文件。
- 攒够几篇新成品 → 回看新成品和人设文件对一遍：哪条被反复打破（说明它不是常量，删掉或降级）、
  哪条反复出现却没写进来（补上，附证据）。
- 换账号 → 复制一份新人设文件，改事实与语气两节，重跑「从成品抽指纹」。
