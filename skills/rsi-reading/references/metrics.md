# 指标口径

一个改进项如果没有对应的指标，就先补度量，别先动手改——
否则永远分不清"变好了"和"我觉得变好了"。

所有指标都必须能从文件算出来。`scripts/rsi.py` 实现了标 ✅ 的那些。

## 闭环健康

| 指标 | 定义 | 怎么算 | 状态 |
| --- | --- | --- | --- |
| 闭环覆盖率 | 走到"发布"的书 / 全部书 | `rsi.py coverage` 的发布列 | ✅ |
| 断点数 | 每条链上"上一步有、下一步没有"的处数 | `rsi.py coverage` 的「断点」段 | ✅ |
| 孤儿产物 | 有成品但认不出是哪本书的目录数 | `rsi.py coverage` 的「孤儿产物」段 | ✅ |
| 端到端周期 | 读完 → 发布 的天数 | 卡片 `read_at` → 平台发布/排期时间 | ✅（近似） |
| 全周期 | 开始读 → 发布 | 需要记录"开始读"的时间戳 | ❌ 未埋点 |
| 用户介入次数 | 一次流程里需要用户亲自纠正/补做的处数 | 人工记一行：时间 + 哪一步 + 改了什么 | ❌ 未埋点（口径见 R20） |
| 排期落在窗口内 | "下一个空档"是否在平台定时窗口（今天 + 13 天）内 | `plan.py ready` 的「空档在平台定时窗口内」 | ✅ |
| 发布回读真假 | "工具报成功"与"平台存下的时刻"是否一致 | `xhs.py verify-scheduled` 回读卡片时间 | ✅ |

## 内容合规（指令遵循）

规则本身不是指标，"规则有没有被遵守"才是。这一节量的都是**成品对 `rednote-post` 规则的服从度**，
全部由 `skills/rednote-post/scripts/check_content.py` 判定（`plan.py ready` 已并进闸门）。

| 指标 | 定义 | 怎么算 | 状态 |
| --- | --- | --- | --- |
| 半成品标记数 | 成品里出现「待核实／需查证／据称…」的处数 | `check_content.py`（正文 + `build/*.html`） | ✅ |
| 正文加粗处数 | `body.txt` 里 `**` 的出现次数（平台不渲染，原样显示） | 同上 | ✅ |
| 强调色合规 | `build/card.css` 的 `--accent` 是否 `#FD6408` | 同上 | ✅ |
| 封面素材合规 | 封面文件存在、RGB、宽度 ≥ 交付画布下限 | 同上 | ✅ |
| 版本唯一 | 有没有 `body-v2.txt` 这类并存版本 | 同上 | ✅ |
| 封面真实性 | "是不是这本书真实存在的封面" | ❌ 机器判不了——只 warn（要求 `manifest.json` 的 `cover.source`），接 R57／R51 |
| 人设：AI 味词 | `persona.md` 反面清单里的词（综上所述／底层逻辑／抓手／赋能／颗粒度…）出现在正文的处数 | `check_content.py` 的 `scan_persona` | ✅ |
| 语义留后路 | "这句话读者会不会读成作者在留退路" | ❌ 只靠禁用词兜底（写了才抓得住） |

**口径**：前五项是非 0 即 1 的硬闸门（全过才允自动发布）；后两项是已知的能力缺口，
不计入闸门，避免"假装有数"。

## 供给侧（会不会断更）

| 指标 | 定义 | 现状 |
| --- | --- | --- |
| 选题缓冲 | 未用选题数 ÷ 每日发布数 | **0 天**（`topics.md` 里没有一条没用的）→ R1 未解 |
| 成品缓冲 | 已备好未发的成品数 | 14（已排到 **2026-10-20**；日更 7/周，≈2 周） |
| 素材缓冲 | 已有笔记但没做成的书 | **0**（17 本书全部出过成品；没有"读过但还没做成"的存量可再切一角） |

**红线**：选题缓冲 < 7 天就是断更风险。这条比任何视觉优化都优先。

## 需求侧（有没有用）——必须按渠道分开算

**S4 是分支，不是节点。** 度量也要跟着分支走：每个渠道有自己的信号，
不能拿小红书的指标代表整条链（私域没有 reads，自用渠道没有赞，对话式取用没有收藏）。

先记账，再算比率。每个渠道至少要有"渠道名"和"取用计数"两个字段。

| 渠道 | 能拿到的信号 | 现在 |
| --- | --- | --- |
| 公开社交：小红书 | reads / likes / collects / shares | ✅ `state/state.json` 的 `history.published`（18 条带这四个字段；扫描是 partial，须与 `scheduled-verified.json` 互相印证）。**这份数据在样本 #8–#9 一直是空的**（R52 修完才回来），`#10` 之后每次 `queue` 扫描都不再抹掉它——**样本 #11 是修完之后的第一次实战，`history` 确实留住了** |
| 公开社交：小红书（**数据看板**，2026-10-11 起） | 曝光 · 封面点击率 · 收藏 · 涨粉 · 分享 · 人均观看时长 · **同类分位** · 观看来源 · 观众画像 | ✅ `state/analytics/analytics-YYYY-MM-DD.json`，由 `skills/rednote-post/scripts/analytics.py fetch` 落、`report` 出表。比 `state.json` 那一路厚得多，且**分位是同类归一化的**（原始比率在几十观看量下是噪声，分位不是）。**目前要手动 fetch → R71** |
| 私域（朋友、群） | 回复、追问 | ❌ 无记录 |
| 自用（笔记、日记） | 是否回看 | ❌ 无记录 |
| 对话式（second-brain 回答） | recall 命中与采纳 | ❌ 未埋点 → R2 |
| 单页 / 打印版 | 是否读完、是否被再引用 | ❌ 无记录 |

小红书这一个渠道的指标（下面这些，只有它算得出来）：

| 指标 | 定义 | 怎么算 | 状态 |
| --- | --- | --- | --- |
| 曝光 / 观看 | 平台给的量与人真的点进来的量 | `state/analytics/` 的 `imp_count` / `read_count` | ✅ |
| **封面点击率 + 同类分位** | 封面把曝光换成点击的效率；分位 = 超过多少同类作者 | 同上 `coverClickRate`；分位取 `base.<id>.analyse_infos[quota=clickRate].scale` | ✅ |
| **收藏率** | 收藏 ÷ 观看 | 同上。**本号的小红书支线目标**——收藏最接近北极星（"以后用得上"） | ✅ |
| 同类内容分位 | 内容丰富度／内容深度／互动表现 的分位 | `analyse_infos` 的 `contentRich` / `viewTimeAvg` / `noteEngage` | ✅（平台约一天后出） |
| 观看来源 | 首页推荐／搜索／视频推荐… 的占比 | `source.<id>.source[]` | ✅（观看 ≥100 才有） |
| 观众画像 | 性别／年龄／城市／兴趣 | `source` 明细接口 | ✅（观看 ≥100 才有） |

| 指标 | 定义 | 怎么算 | 状态 |
| --- | --- | --- | --- |
| 阅读量 | 平台 reads | `state/state.json` 的 `history.published` | ✅ |
| 收藏率 | 收藏 ÷ 阅读 | 同上。**读书类内容看收藏率，不看点赞** | ✅ |
| 互动率 | (赞+藏+转) ÷ 阅读 | 同上 | ✅ |
| 关注转化 | 新增关注 ÷ 阅读 | 平台未抓，需补 | ❌ |

注意：单篇 reads 在几十的量级时，任何比率都是噪声。
样本 < 20 篇时只看趋势，别下结论；跨渠道比较时更要小心——口径根本不同。

## UI 侧（同一份内容，不同载体好不好读）

载体的好坏不靠感觉，靠可测的东西。随载体不同而不同：

| 载体 | 可测的量 |
| --- | --- |
| 图文卡片 | 字号下限、溢出、压页脚、孤字换行（`rednote-post` 已实测） |
| 单页 HTML | 三栏是否溢出、内容带 headroom（`scandinavian-style` 已实测） |
| 长文 | 分段长度、标题层级 |
| 对话 | 一次回答里被取用的卡片数、回答长度 |

这些是"**呈现**"维度的指标，和渠道指标正交——别混成一张表。

## 取用侧（北极星在这）

| 指标 | 定义 | 状态 |
| --- | --- | --- |
| **卡片取用率** | 被 recall 命中并实际读过的卡 ÷ 书库卡片数 | ❌ 未埋点 → R2 |
| 死卡数 | 从未被任何问题命中的卡 | ❌ 未埋点 → R2 |
| 落空率 | `recall` 返回全是弱匹配的次数 ÷ 总次数 | ❌ 未埋点 → R2 |
| 命中质量 | 采纳的候选排名（第 1 名命中率） | ❌ 未埋点 → R2 |

**北极星：卡片取用率。** 它直接对应这条流水线的目的。
它的反面（死卡数、落空率）同时告诉我们"书库里缺什么"——这是回流 B 的原料。

注意这里的"取用"是**跨所有出口**的：小红书被收藏、对话里被引用、单页被读完，
都算取用。现在的度量只覆盖了其中之一（小红书），所以北极星目前被低估。

| 指标 | 定义 | 状态 |
| --- | --- | --- |
| 单本阅读耗时 | 从开始读到出笔记 | ❌ 未埋点（2 次手记，见下） |
