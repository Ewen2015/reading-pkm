# 如何阅读一本书

把 Adler 的阅读方法论变成可执行的流程。关键不是背规则，而是**按层次组织阅读，在正确的时机做正确的事**。

## 四种阅读层次

层次是累积的（高层包含低层）。先判断任务落在哪一层，再动手。

| 层次 | 回答的问题 | 何时用 |
| --- | --- | --- |
| 基础阅读 | 这个句子在说什么？ | 生字、外语、术语卡住理解时 |
| 检视阅读 | 这本书在谈什么？值不值得细读？ | **任何一本书的第一步** |
| 分析阅读 | 这本书到底在说什么？说得对不对？ | 值得精读的书；用户要求拆解／笔记／读书报告 |
| 主题阅读 | 围绕一个问题，这些书合起来在说什么？ | 用户给出主题或书单，要求对比研究 |

**检视阅读永远先行。** 即便用户要求"精读"，也先花几分钟建立地图再进细节。反过来，若检视后判断这本书不值得细读，就停在检视阅读并说明理由。

## 书的金字塔：决定投入多少

- 99% 的书只提供娱乐或资讯 → 扫描即可，不要做分析阅读。
- 极少数的书值得**完整地做一次分析阅读**；读透一遍、笔记做好，就可以放回架上。
- 再少（不到一百本）的书值得反复重读——读完你会觉得"好像还有什么没弄清楚"，那种书才是。

不要对所有书一视同仁。这是本 skill 最省时间的一条判断。

## 四个基本问题

1. 整体来说，这本书在谈些什么？
2. 作者细部说了什么，怎么说的？
3. 这本书说得有道理吗？全部有道理，还是部分有道理？
4. 这本书跟我有什么关系？

**顺序不可颠倒**：没答完 1、2 就没资格回答 3；批评之前必须先了解。

## 工作流

### 1. 定层次与目标
先分清用户是要**消遣／取资讯**，还是要**求得理解**——只有后者才需要分析阅读。据上表选定层次，并在回复中说明你的判断和理由。

### 2. 检视阅读（必做）
读 `references/inspectional-reading.md`。产出：分类、一句话大意、基本架构、值不值得细读的结论。
如果读物是 PDF/EPUB，先用 `scripts/extract_book_text.py` 抽出带页码锚点的正文与目录，再据此作答。

### 3. 分析阅读（按需）
读 `references/analytical-reading.md`，按三阶段十五条规则走。最吃重的是规则 1（分类）、4（作者的问题）、5（关键字与词义）、7（论述结构）。
再按书的类型调整：`references/by-genre.md`（实用书／文学／历史／科学／哲学／社科各有不同读法）。

### 4. 背景脉络（每次都要做）
读 `references/context-and-influence.md`，梳理五个维度：**目的、思潮脉络、作者的思想脉络、上游（影响这本书的）、下游（这本书影响的）**。
最后两项就是「隐身人」——那些不在正文里、却决定了这本书形态的人。用表格呈现：谁 / 关系 / 具体是什么 / 依据。
务必先读完正文再查脉络，且不得编造影响关系（详见该文件「三个必须避开的错误」）。

### 5. 主题阅读（按需）
读 `references/syntopical-reading.md`，走五个步骤。注意角色反转：**书为你服务，而不是你去服务书**。

## 默认交付物

默认给出下面这套笔记；用户只要其中一部分时按需裁剪。分三层：**外**（书在思想地图上的位置）、**内**（书本身）、**评**（你的判断）。

**外 · 脉络**

1. **目的**——作者要解决什么问题、写给谁、想说服谁
2. **思潮脉络**——这本书处在什么思想潮流中，在回应什么
3. **作者的思想脉络**——它在作者作品序列里的位置，以及他思想的变化
4. **上游**——影响了这本书的人与思想
5. **下游**——这本书影响了谁、什么思潮；被如何引用与批判
6. **隐身人表**——谁 / 关系（上游或下游）/ 具体是什么 / 依据

**内 · 正文**

7. **书目与分类**——论说性还是想像文学；理论性（历史／科学／哲学）还是实用性（规则 1）
8. **一句话主旨**——用最简短的话说出全书在谈什么（规则 2）
9. **全书大纲**——主要部分 + 各部分要点，标页码（规则 3）
10. **作者要解决的问题**——主要问题与次要问题（规则 4）
11. **关键词表**——作者的关键字 → 他在这本书里赋予它的词义（规则 5）
12. **关键主旨**——用自己的话复述，附原句与页码（规则 6）
13. **论证结构**——前提、推论、结论，以及作者的隐含假设（规则 7）
14. **未解决之处**——作者解决了什么、没解决什么（规则 8）

**评 · 判断**

15. **评论**——仅当用户要求时给出，且必须走规则 9-15
16. **四个基本问题的回答**

笔记形态对应层次：检视阅读→结构笔记，分析阅读→概念笔记，主题阅读→辩证笔记。定义见 `references/inspectional-reading.md`。

### 一页纸模式（one-pager）

用户说「一页纸」「one-pager」「篇幅太长了，保证内容都在里面」时，把上面那套笔记压成**一页**。
压缩的是篇幅，不是证据——页码、来源和不确定词一个都不许丢。

一页纸只放**外·脉络 + 内·核心**，判断压成一句话。字段固定为：

1. **眉标**——左：文件性质（如「阅读笔记 · 意会认知」）；右：作者 · 原著年份
2. **书目行**——书名（原名）｜编者／译者｜版本｜原书出版社与年份
3. **导语**——这本书要回答什么，一到两句
4. **写作目的／起点问题**——他要解决什么、要说服谁；有没有一个明确的对手
5. **作者的思想脉络**——他凭什么问这个问题（学术出身、转向、政治处境）
6. **核心机制 2–4 条**——书的正面论证，每条附页码
7. **结构地图**——部分 × 篇／章 × 页数，配一条按篇幅的比例数据条，标出全书重心
8. **隐身人**——上游（影响这本书的）/ 下游（这本书影响的），各 3–8 条，每条带依据
9. **读法**——不必顺序读的路线，或最该先读的部分
10. **一句话评价**——你同不同意、代价是什么
11. **来源与可信度注**——哪些是二手、哪些没核对、哪些已过时

版式不要自己发明：用 `scandinavian-style` skill 的密集单页模板
（`assets/one-pager.html` + `references/one-pager.md`），它给定了三栏坐标、字号下限和实测方法。
该 skill 不在环境里时，仍按上面这套字段写，并沿用「先把不确定性标清楚」的原则。

**不要让版面挤掉限定词。** 影响关系没把握就写「需查证」，出处是二手就写明二手——
一页纸最容易犯的错，是为了塞下更多条目而把「据报」「未经核对」删掉。

## 铁律

- **批评前先了解**（规则 9）：说出"我不同意"之前，必须先能说出"我了解了"。做不到就暂缓评论。
- **批评只有四个合法标准**：知识不足、知识错误、不合逻辑、分析不完整。不在这四项内的反对意见不要写进评论。
- **区分作者的观点与你自己的观点**（规则 11）：笔记里要能一眼看出哪句是作者的，哪句是你的。
- **第一遍读难书不停下来查证**——这是检视阅读的规则，不是偷懒。
- **引用落到页码**，方便用户回查原书；**没有印刷页码的电子书**按「章节 + 小节/信件日期」定位，
  并在笔记版本行里说明「电子版无可靠页码」，不要编 p.123。
- **时间跨度先算再写**：用首末年份相减（1932–1961 = 29 年），年龄按生年核对；
  不要凭印象写“四十年”“半辈子”。
- **想像文学不用论说性的标准批评**（见 `references/by-genre.md`）。
- **主题阅读不预设立场**——追求"辩证的客观"。
- **不编造影响关系**——时间在后不等于受其影响。没有引用、师承或自述证据的脉络联系不要写；拿不准就写"需查证"。
- **一页纸也留页码与不确定词**——版面小不是删证据的理由；压缩的应该是篇幅，不是限定条件。

## 笔记的下一步

写完笔记后，如果用户在用 `second-brain`（第二大脑），可以把这份笔记喂进去：

```bash
python3 <skills/second-brain>/scripts/brain.py add --notes <这份笔记的路径> --slug <slug>
```

它会把这份笔记收进书库（默认是仓库根的 `library/notes/`），并生成一张可检索的卡片骨架；
正文六节由人从上面的「内·正文 / 评·判断」里提炼。
**触发词要用用户会说的话写，不是章节标题**——卡片写法的口径在那个 skill 的
`references/cards.md`。
